项目位于 `FlowerBreath/`，原来的《灵羽 · 万物生》项目保持原位置。此项目自己的隐藏设置也保留原图生命模式。

## 手势

| 操作 | 手势 |
|---|---|
| 展开花瓣 | 右手后三指收拢，拇指与食指逐渐分开 |
| 收拢花瓣 | 右手双指捏合 |
| 半开停留 | 双指距离保持不变 |
| 下一花境 | 右手五指张开，无需移动；五朵花按顺序循环 |
| 花瓣飘落与轻摇（第1、3朵） | 右手双指展开≥90%，同时左手五指张开并稳定约120ms |
| 原视频动态泡泡（第5朵） | 左手五指张开播放；收拢或片尾退出，收拢后重新张开可重播 |

开合是手指间距对应素材进度，不是触发播放/倒放；可随时反向。距离按手掌尺寸归一化。短暂丢手保持当前位置，少量已有平滑继续收敛。

右手后三指收拢时，双指间距连续控制开合；右手五指张开约120ms触发下一朵，顺序为1→2→3→4→5→1。张掌换花时保持最近的开合进度。左手负责第1/3朵的落瓣和第5朵的原视频泡泡，不切换花境。

持续张掌只触发一次，短暂或较长丢手也不会解除此保护。右手收回双指姿态或握拳约100ms后，再次张掌即可继续换花。短暂检测抖动不会重新触发；转场期间的额外张掌不会排队执行。旧版原图生命模式继续沿用其自身手势。

右上角“···”收纳摄像头开关、重置、全屏、预览、骨架、左右手交换、操作说明。左右手标签不符合实际时先关闭摄像头，再勾选交换。花境模式不会触发蝴蝶和树。

**文字处理（修订）**：取消静止首帧补丁；旧方法会固定住局部枝叶，还遗漏水印入场光晕。现在每帧只根据自身周围的干净背景计算二维平滑修补，再羽化边缘，不复用静止图块。第1、2、3、5段覆盖右下角动画范围；第3段截掉闭合后无效停留并避开左上角标记，第4段选同一视频后半段的等效反向开合，让水印位于左上空背景，保留右下运动叶片完整。主体没有重画，手势规则与五朵顺序不变。修补区域是低细节背景近似，不是恢复被文字挡住的真实纹理，可能较周围柔和。

新增晴空樱花含两簇不同步开合的花：上方花簇收拢时下方仍有部分花瓣展开，这是原视频内容，未重画成完全闭合。原素材中的落瓣与背景依旧随手势进度暂停或反向；控制和转场逻辑未更改。

**清晰度**：保留 1280×720，应用轻度受限锐化，单通道增强限制在 6/255。没有超分辨率、虚构细节或把低清素材宣称为 4K。已有浅景深虚化保留。

**背景限制**：实际检查没有发现明显剪切或快速运镜，主要是枝叶、散景和轻微漂动，因此保留完整画面。背景没有独立分层，细小枝叶与素材自带闪光仍会随手势暂停、反向；不能宣称完全解决背景倒放。独立微光粒子持续运行。若需要明显流水/镜头运动素材的背景独立播放，需要进一步分层处理。

## 转场与性能

约 0.95 秒的局部噪声遮罩从花心向周围推进，粒子先扩散再聚拢。避免两幅完整花朵长时间透明叠加；边界仍有短暂柔和融合。下一花境准备好当前开合位置后才开始过渡，右手始终可继续控制。

非16:9窗口保持视频完整比例，外围使用低频模糊暗部延展；没有拉伸主体或为填满窗口裁掉主要花瓣。桌面横屏适合观看，竖屏中花朵显示区域相对较小。

- 解码帧 LRU 上限24张：720p RGBA约84.4 MiB，另有最多3个在途加载/解码，以及浏览器/GPU自身资源。这不是进程总内存上限。
- 实际画面使用GPU着色器混合前后缓存帧：小数开合进度只更新插值参数，不再每帧用CPU画布重画720p图片。仅源帧变化时上传纹理，最多4个复用纹理槽；未转场时不绘制下一朵。大幅形变仍可能有轻微融合，这不是光流补帧。
- 优先预取当前花境前后帧；闲置时下一朵只预载固定少量帧，不随每次捏合重复解码。转场启动后才更新它的目标进度；不一次解码全部视频。
- 过时请求取消，不积累待执行寻帧；淘汰的 ImageBitmap 调用 close。
- 摄像头由本地 Worker 推理，最多一帧在途，使用完关闭 ImageBitmap。
- DPR最高1.5，持续慢帧时降至1，微光数量从1000降至500。

## 检查与复现

```powershell
npm.cmd run build
npm.cmd test
node scripts/browser-test.mjs
```

浏览器测试需要 Chrome、开发服务器5180端口。`?testHarness=1` 仅开发环境提供合成关键点测试入口，正式界面不含手动选花按钮。

素材检查/重新生成处理帧：

```powershell
node scripts/inspect-hd.mjs
npm.cmd run prepareVideos
```

以上脚本在本机 Chrome 解码，没有云端视频处理。更换素材后需重新检查区间和标记位置，不能沿用旧参数假装自动适配任意视频。脚本会重建衍生帧，原视频始终保留。

测试范围、硬件未验证事项见 `TESTING.md`。实际真人手势成功率、端到端延迟与稳定帧率尚未验证。

## 连续开合性能优化（2026-11-03）

`node scripts/perf-test.mjs before/after` 为同条件10秒合成连续手势测试，前2秒热身，随后统计requestAnimationFrame间隔。优化前均值33.96ms、P95为50.1ms；优化后均值16.67ms、P95为16.8ms。统计窗口中超过33.4ms的帧间隔由99次降为0次。解码完成次数由694降为361，两个版本缓存峰值均24张。报告在 test-results/browser/perf-before.json 与 perf-after.json。

这是本机无界面Chrome的短时合成输入对比，未接真实摄像头，不能代表所有设备的帧率或真实手势延迟。原素材仍为24FPS；GPU混合改善显示连续性，没有生成新的真实运动细节。

## 清晰度与亮度优化（2026-11-03）

显示着色器增加轻量的亮度细节增强：只增强已有边缘，用噪声门限、局部颜色范围和强度上限抑制白边，不锐化用于画面比例延展的模糊背景。在线性颜色空间提亮中间色调，保留黑位与白色高光。原视频和处理帧均未改写，仍为720p，不是AI超分或细节重建。

相邻视频帧仍在GPU中混合；缓存不足、两张可用帧相距超过2帧时，暂用较近的一帧，避免把明显不同的花瓣轮廓混出重影。性能降级时关闭额外锐化采样，保留提亮与连续控制。

`node scripts/quality-test.mjs before/after` 保存四种花半开/全开的同条件截图和显示亮度统计，路径为 `test-results/quality/`。本次8组画面的平均显示亮度提升约10%～19%，不代表实际分辨率提升。`node scripts/perf-test.mjs clarity` 测得平均帧间隔16.67ms、P95 16.9ms，锐化保持开启；这是合成输入的短时渲染测试，未验证真人摄像头延迟。
